## Decisions Made

1. **Owner is assumed, not required.** Missing owner / no people configured is a `warn`, never a
   `fail`. The warning names the consequence. This is the deliberate fail-soft exception for optional
   contact infrastructure (saved to memory).
2. **Constraint framing: "single human user (the owner)."** `docs/constraints.md` headlines a
   person-count constraint, with the two non-relaxations (one user ≠ one task, one user ≠ one plugin).
3. **Pure inspect-fn + thin shells (FCIS), not an observer in `PeopleDirectory`.** One pure
   `inspectPeopleDirectory` is the single source of truth for people-config health; bootstrap logs the
   warnings, doctor renders them. `PeopleDirectory` stays a pure lookup table.
4. **One dedicated doctor "People Directory" category.** Consolidates owner-presence + single-user +
   owner-channel validation; the owner check moved out of "Config Files" and the role-vs-roles bug is
   fixed. Channels derive from enabled, send-capable built-in comm manifests (doctor sees bundled
   plugins; the daemon validates the live registry).
5. **Channel validation runs at both startup and doctor** (per D9's "config load / doctor").
