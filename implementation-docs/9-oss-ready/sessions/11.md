## Decisions Made

1. **`setup.sh` PATH handling — detect, offer, relink, exit clean (owner-refined).**
   After `pnpm link --global`, if `engineer` is not on PATH, a sub-prompt offers to run
   `pnpm setup`. Confirm → run it, re-link, close with a restart-your-terminal message.
   Decline → exit 0 with manual steps; install + build are already saved. Never edits
   the shell profile without consent.
2. **Shared `scripts/lib.sh`** over self-contained scripts — one source of truth for
   output style and the actionable failure helper.
3. **Node-version preflight in `setup.sh`** — pnpm only warns on an engine mismatch, so
   a wrong Node version is caught early with a clear message instead of failing cryptically.
4. **`reset.sh` seed is explicit and optional** — no-arg runs interactive setup; a seed
   argument that is missing/not-a-directory/unreadable is a hard error. A bare `reset.sh`
   no longer auto-seeds from `seed-example/` (documented in the script header).
5. **No "linked but not on PATH" guard added to `setup.sh`.** Analyzed: if the first
   `pnpm link --global` succeeds, `PNPM_HOME` is in the shell — and the normal `pnpm setup`
   mechanism writes the `PNPM_HOME` env and the `PATH` entry together. So link-succeeds-
   but-not-on-PATH needs a deliberate half-finished manual config — unreachable in practice.
6. **No npm-publish entry added to `future-considerations.md`.** `future-considerations.md`
   is for ideas with no planned home; npm-publishing is a committed future Phase 9 concern,
   so a duplicate entry would just risk drifting stale. The publish prerequisites are
   recorded here instead (see below).

## npm-Publish Prerequisites (recorded for the future publishing slice)

The Phase 2 work built the **contributor-from-source** path (`pnpm run setup`). The
**published-package** path (`npm install -g the-engineer` → `engineer start`) is separate
and coexists — `scripts/setup.sh` / `reset.sh` are dev tooling and would not ship. Nothing
in Phase 2 conflicts with or needs redoing for publishing. Already correct: `package.json`
`bin` (`engineer` → `dist/index.js`). Still needed when the publishing slice happens:
a `files` whitelist (ship `dist/` + migrations, not `src/`/`scripts/`/`seed-example/`/
`implementation-docs/`), a `prepare`/`prepublishOnly` build hook, a decision on what ships
and whether `npx the-engineer` is supported. CLI version single-sourcing is already planned
as Slice 4 Phase 5 (D9).
