## What Happened

Implemented Phase 7: Task Engine. Built the `TaskEngine` class with state machine validation, permission enforcement (Gate 1), task CRUD, hierarchy queries, field updates, and cost tracking. Created `createTestTaskEngine()` helper. Updated Protocol P2 (intake→queued is now caller-driven, not automatic). Updated build order docs. 79 new tests, 749 total.

## Decisions Made

1. **No auto-transition intake→queued.** `createTask()` returns task in `intake` state. Caller (Daemon) explicitly transitions to `queued` via `requestTransition()`. Gives granularity window for future enrichment/validation. Protocol P2 updated to reflect this deviation from original spec.
2. **Extended scope beyond build order spec.** Added `getChildren(parentId)`, `updateTaskField(taskId, field, value)`, and `getStateHistory(taskId)` — trivial methods needed by Phase 8-9. Build order annotated.
3. **Conditional permission returns metadata.** `checkPermission` for `merge` in `review_pending.code` returns `{ allowed: true, conditional: "auto_merge configured for repo" }`. Action Pipeline (Phase 9) evaluates the condition. Task Engine stays decoupled from config.
4. **`isValidTransition()` as exported pure function.** Mirrors `matchesPattern()` in EventBus — testable independently.
5. **`subStateMatches()` helper** extracted to reduce cognitive complexity below Biome's threshold of 15.
6. **`rowToTask()` exported** for test helper use, following `rowToEvent()` pattern from EventBus.
7. **Build order "13 transitions" corrected to 25.** `ValidTransitions` has 25 entries, not 13 as the build order originally stated.

## Fresh-Lens Observations

- The `repo` field in `task.created` event payload is not stored on the task table — it's event-only context. Architecturally correct: events capture creation-time context.
- `from_sub` undefined vs null matching in ValidTransitions requires careful semantics: undefined means "state has no sub-state" (not "any sub-state").
- Conditional permissions can't be evaluated by Task Engine (no repo config access). Clean separation via metadata return.
