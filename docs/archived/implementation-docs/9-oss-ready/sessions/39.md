## Decisions Made

The panel reshaped the Session 38 draft substantially. Final locked architecture:

1. **Routing is a `next(result, ctx): Route` function per sub-phase, not a declarative RoutingRule[] + predicate DSL.** All 3 panelists independently called the DSL "a small programming language." The function is modular (own files) and linear (reads top to bottom), shows in stack traces.
2. **The handoff: agent reports a 3-word outcome (`ok`/`needs_human`/`failed`); the orchestrator's `next` owns the route.** The agent never names a phase. Kills the mis-route bug class and the `next_phase`-overloading hack. Richness (refine's verdict) is local + Zod-validated in `details`. We don't trust the self-report — verify + review re-check downstream.
3. **`cli-run.ts` is the single defended boundary** for the opaque agent subprocess (spawn/retry/validate/recover/signal). Dumb routing, smart boundary.
4. **Two loop counters, both on the checkpoint:** `phase_iteration` (intra-phase repeat, resets on phase entry, per-phase cap; Review=3) + `total_reworks` (inter-phase jump, per-dispatch global backstop). Reset on fresh dispatch → human-driven external reworks stay unbounded.
5. **Crash ≠ pipeline failure — retry-policy untouched.** Pipeline (sub-phase) failures block with typed reason. Crashes keep Slice 6's `crash` category (backoff + cap, poison-task protection). REVERSES the earlier "cut crash category" decision. Shrinks Slice 8 scope.
6. **Typed `PrEvent` vocabulary with stateless merge-readiness.** Plugin emits `pr_ready_to_merge` only when approved+CI-green+mergeable together → deletes the in-memory `approvedAwaitingCI` map and its restart bug.
7. **External events re-enter via DB re-queue + `entryFor` map, not a back-channel `applyExternalEvent` call.** Keeps the daemon→orchestrator boundary acyclic + crash-safe; merge runs in a normal dispatch (abortable, observable).
8. **Arbitration, dedup, authorization are Core policy** (not pushed into the plugin). `arbitrate(events)` picks one winner per tick.
9. **Structured block payload** `{reason, sub_phase, category, needed}` — typed keys, not prose (honors strict-data-invariants; Slice 13 dashboard reads keys).
10. **Build dark, cut over atomically.** Build the full pipeline/ unwired (legacy stays live+green), then one cutover commit (swap executeTask, delete legacy, finalize schema). Pre-v1 DB wipe = no task straddles runners. REVERSES the earlier parallel-runner-per-phase migration (panel: checkpoint corruption window).
11. **Audit `blocked` semantic consumers** (health-monitor/unblock-resolver/response-poller) for `pr_review_pending` so stuck-detection doesn't false-alarm on PRs awaiting review.
12. **Auto-merge preserved** (corrects a Session 38 sloppy lock): approval is the trigger, The Engineer performs the merge, merge is terminal. Refactored onto typed events; `auto-merge` is an entry-only orchestrator sub-phase.
13. **One default review lens** (`self-review`) + opt-in lenses; `refine` fixes in place and `repeat`s (cap 3), `jump`s out only when it can't fix. Matches the system's best historical behavior.
14. **Config-driven deliverable** (`skip_pr_creation`): PR mode → merged PR ("done when merged"); push-only → pushed branch ("done when pushed"). Delivery sub-phases skip-gate on it. Second concrete use of the skip-gate mechanism.
15. **Slice 8 ships data, not dashboard UI** — all UI for the new shape → Slice 13.

Plus refinements found beyond the panel: stateless `pr_ready_to_merge`, observability emitted by the runner (a step can't forget to log), `details` validated per sub-phase, `cli-run` as the concentrated risk boundary.

Folder structure locked: `src/core/orchestrator/pipeline/{runner,types,pipeline,cli-run}.ts` + one folder per phase + one file per sub-phase. 6 phases: requirements → research → planning → execution → review → delivery.
