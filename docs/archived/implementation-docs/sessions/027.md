# Session 27 — 2026-03-09

## What Happened

Designed deployment and operations: data directory layout, operational logging, daemon process management, CLI interface, health check (`doctor`) command, and first-run experience. Adopted two patterns from the OpenClaw review: `doctor` command (10 check categories) and rolling file logging (pino + pino-roll).

All questions resolved through Q&A — 5 design questions discussed before writing. Every decision passes the dual test: works for v1, doesn't block future evolution. No paid infrastructure required — everything runs locally on the developer's machine.

## Decisions Made

1. #109 — Data directory layout: `~/.engineer/` as unified root with `config/`, `data/`, `logs/`, `workspaces/`, `run/` subdirectories. `ENGINEER_HOME` env var override.
2. #110 — Logging strategy: pino (structured JSON) + pino-roll (daily rotation, 500MB cap, 7-day retention). Single file with component tags. Complementary to Event Bus audit trail.
3. #111 — Logging configuration: new `logging` section in DaemonConfig (level, dir, max_size_bytes, max_files, console).
4. #112 — Process management: foreground default, `--daemon` for background. PID file for single instance enforcement. SIGTERM/SIGINT graceful shutdown. Exit codes 0/1/2.
5. #113 — OS service integration: `engineer install` generates launchd plist (macOS) or systemd unit (Linux) with instructions. Does NOT auto-register.
6. #114 — CLI framework: commander (validated by OpenClaw, 26k stars, TypeScript support).
7. #115 — CLI command inventory: 8 commands (start, stop, status, logs, init, doctor, install, config validate). Flat structure, future-compatible.
8. #116 — `doctor` command: 10 check categories (runtime, dirs, config, secrets, database, plugins, GitHub, Telegram, workspace, risky configs). Pre-flight subset (1-6) runs on every `engineer start`.
9. #117 — First-run experience: auto-create directories, initialize database, run pre-flight, fail-with-instructions if secrets missing. No interactive wizard.
10. #118 — `engineer init`: generates directory structure and template config files (core + all plugins). Safe to re-run. `--force` to overwrite.
