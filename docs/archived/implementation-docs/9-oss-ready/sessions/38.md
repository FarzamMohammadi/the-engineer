## Decisions Made

1. **Cut the `integration` phase entirely.** Dead surface since Slice 6 deleted decomposition. Removes the enum value, schema, prompt builder, dir, skill mapping, trace dir, demo_prep's "if decomposed child" routing branch. PHASE_SEQUENCE shrinks; `demo_prep` becomes terminal (later renamed/merged into Delivery).
2. **6-phase canonical order:** Requirements → Research → Planning → Execution → Review → Delivery. `self_review` becomes a top-level Review phase (not a sub-step of something else); `demo_prep` collapses into Delivery alongside commit/push/PR creation.
3. **Phase + state model:** `phase` = where in the lifecycle; `state` = active vs blocked; `phase_iteration` = intra-phase loops (Review primarily). All three persisted on the task row, all observable, all in dashboard.
4. **`Outcomes.review_pending` collapses to `blocked(reason=pr_review_pending)`.** `TaskStates.review_pending` removed from the state machine (ValidTransitions + PermissionTable surgery). Same mechanism as `need_more_info` blocking — the structured `blocked` field carries the reason taxonomy.
5. **Sub-phase registry as load-bearing architecture.** Each top-level phase has 1+ sub-phases declared as data (name, prompt/handler ref, session-result requirement, skip-gate, config gate, routing declarations). Phase-runner is generic over the registry. Adding/removing/toggling a sub-phase is config + one new file. Tests follow the registry, not hardcoded phase shape. Slight over-engineering for evolvability is sanctioned.
6. **Slice 8 absorbs Slices 9 + 10 in full** (Demo & PR + Review & Feedback External). One coherent architectural unit lands together. Subsequent slices (was 11-16) renumber down by 2. Slice 11 boundary preserved (workspace cleanup stays Slice 11).
7. **Review loopback:** intra-phase iteration capped at 3 (configurable). Refinement can declare early escape route at any iteration (Planning / Requirements). Cap-hit unconditionally blocks — workflow-level red flag, loud by design.
8. **One default Review lens:** `self_review` (broader self-review that combines requirements-check + obvious code smells + completeness, leveraging refactor-guide.md ideas). Other lenses (security_review, code_quality, architecture_review) opt-in via config. Refinement always-on.
9. **Delivery sub-phases:** `pr_description` (CLI) + `pr_push` (orch) + `pr_create` (orch) + `await_review` (orch block).
10. **Typed external event routing** from GitHostingAdapter: 5 event types. `pr_comments` → Requirements (with skip-gate fast-path for simple comments); `pr_ci_failure` → Execution; `pr_merge_conflict` → Execution; `pr_approved` → informational only (notify owner, dashboard signal); `pr_merged` → terminal completed.
11. **Failure policy:** every failure blocks with descriptive typed reason. No abandonment paths. `engineer retry` is the unblock verb (semantically becomes "unblock-and-resume"). Resume from failed sub-phase, not phase start. Loud signaling, operator-recoverable.
12. **Rework feedback context** as structured data: every loop-back sub-phase prompt gets a "Why You're Back Here" section with event type, raw content, file refs, CI logs, conflict files. Untrusted content wrapped via `wrapUntrustedContent`. No loose feedback strings glued to prompts.
13. **Outreach batching:** requirements gather writes ONE file per contact with ALL questions in it (locked adaptation of dev-toolbox's "one question at a time" — which is interactive-only).
14. **`retry-policy` module shrinks to a single `agent_unavailable` category.** Crash category cut (catastrophic failures go straight to block, per the every-failure-blocks model). Auto-recovery preserved for genuine transient agent unavailability.
15. **Execution splits into `implement` (CLI) + `verify` (orchestrator: typecheck + lint + tests).** Verify-failure loops back to `implement` with structured failure context. Logical commits land during `implement`; `pr_push` is the safety net (resolves the long-standing TODO in `pr-manager.ts:154`).
16. **Per-sub-phase checkpoints.** Each sub-phase's completion writes a checkpoint. Resume picks up at the failed/next sub-phase. Composite resume key (`phase + sub_phase`).
17. **Sub-phases execute sequentially in v1.** `docs/constraints.md` gets "Sub-Phase Execution Order" entry. `docs/future-considerations.md` gets "Parallel Sub-Phase Execution" capability concept.
18. **`thoughts/` layout:** `thoughts/{task}/{phase}/{sub_phase}/output.md` + `session-result.json` per CLI sub-phase. Symmetric with traces dir. Self-contained sub-phase units.
19. **Prompt builder organization:** one file per sub-phase, grouped by phase directory (e.g. `prompts/review/self_review.ts`).
20. **Slice rename:** `slices/08-rrpir-phases.md` becomes `slices/08-pipeline-phases.md`. Acronym RRPIR no longer maps to the 6-phase shape.
21. **`engineer retry` verb stays.** Semantically becomes "unblock-and-resume" without adding a new CLI command.
22. **Trivial-skip preserved + generalized as registry skip-gate.** Today's `skip_research` becomes one instance of a generic skip mechanism; full observability for every skip (decision_point + journal + dashboard).
23. **AgentAdapter signal threading end-to-end.** `AgentRunRequest` gains `signal: AbortSignal`; plugins pass it to Node's `spawn({ signal })` natively. Closes Slice 6 → Slice 8 handoff. (Self-unblock path in `orchestrator/index.ts:262` also needs threading — caught during research.)
24. **Dev-toolbox skill port/adapt/skip framework.** Enumerated in requirements doc with per-principle verdicts. Locks: one-question-at-a-time → ADAPT (batch all questions per outreach); observations-vs-inferences split → PORT (research doc template); Decision template Choice/Context/Rejected/Consequence → PORT (planning prompt); refactor-guide cut/keep lists → PORT (self_review lens).
25. **Plan deferred to Session 39 to respect 400k token cap.** Implementation sessions begin in Session 40.
26. **Mid-session tangent:** LLM→Agent rename ran as a separate session before research wrapped. Research surface used the renamed contract. Tangent prompt drafted in this session.
