## Decisions Made

1. **Receive belongs on Telegram, not GitHub** — GitHub is for intake (triggers). Telegram is the communication channel. Response detection goes through CommunicationAdapter `receive`, not TriggerAdapter.
2. **No checkpoint on block** — blocking is a pause, not a completion. No checkpoint means `resume_from=null`, `startIndex=0` (requirements_gathering). Workspace re-registered via existing rework path.
3. **Always set `return_to_phase`** — even when requirements_gathering blocks itself (defaults to current phase). Uniform mechanism for all blocked resume routing.
4. **Persist `thoughts_dir` in TaskWorkspace** — ensures worktree context survives across block/unblock/re-dispatch cycles.
5. **Drain Telegram updates on startup** — prevents old messages from triggering false unblocks.
6. **BlockedDetails must include all schema fields** — `contacted` and `needed` added to prevent future parse-time failures.
