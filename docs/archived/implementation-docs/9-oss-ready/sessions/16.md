## Decisions Made

1. **Post-bootstrap files get a `lifecycle` span around plugin loading.** Plugin loading is non-trivial enough to warrant a span per §14, even though it's a one-time startup operation. The span wraps the entire `loadBuiltinPlugins` flow and ends with the result summary.
2. **Sparse degradation logs get enriched at the source, not at the caller.** `loadPluginConfig` and `createPluginInstance` now log their own degradation context (adapterType, capability, recovery info), matching the pattern Session 15 established. The caller no longer re-logs.
3. **`readonly` is shallow by default; go deep only where the inline type is part of the file.** `PluginLoadResult.failed: Array<{ id: string; reason: string }>` kept its inline element type non-readonly. `BootstrapResult.hints: Array<{ readonly pluginName: string; readonly message: string }>` went deep because the inline type sits beside the interface. Pragmatic call — no value in deep-readonly nested structures that are never reached for.
4. **Skip `as const` on `STATUS_ICONS` lookup table.** Would require `as const satisfies Record<DoctorCheck["status"], string>` to keep the type-completeness check. The verbosity exceeded the value. The existing `Record<...>` annotation already documents completeness.
5. **Optional fields on `readonly` interfaces declare `?: T | undefined`, not `?: T`.** Under `exactOptionalPropertyTypes: true`, the latter forces ugly conditional spreads. The former lets every construction site write the value directly. This is a pragmatic syntax choice, not a documented standard — case-by-case judgment.
6. **Codified "Apply with judgment, never mechanically" in coding-standards.md.** A callout right after the intro, framing how every rule below should be read. Saved a memory linking the principle to the incident that surfaced it so future sessions don't repeat the failure mode.
