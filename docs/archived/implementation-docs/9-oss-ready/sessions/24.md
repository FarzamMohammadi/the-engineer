## Decisions Made

1. **Delete the decomposition consumer surface in full** (D1, slice-06 §Decisions). Schema
   fields, sub-states, ValidTransitions entries, permission table entries, scheduler/daemon
   handler logic, `task.children_all_done` event, `data-lifecycle` reference, bundled config
   block, dashboard client `SubState` type. Cross-slice deletions (decomposition-handler.ts,
   planning prompt instruction, decomposition schemas) handed to Slice 8 along with the question
   of whether the `integration` phase itself is dead. Full restoration roadmap captured in
   `docs/future-considerations.md`.

2. **Single retry-policy module** (D2). New `src/core/retry-policy/` with named categories
   (`crash`, `llm_unavailable`), per-category counter fields on the task row, config-driven
   backoff schedules and ceilings exposed under a new `retry_policy` block in `daemon.yaml`.
   Both scheduler and phase-runner go through `recordFailure(category, taskId)`.

3. **Dispatch-tracker primitive with AbortController contract** (D3). New
   `src/core/dispatch-tracker/`. Per-dispatch identity (`dispatchId` via ulid) for idempotent
   late callbacks. `terminate(taskId, reason)` aborts the signal. New `Outcomes.terminated`
   with typed reason routing. Contract ships in Slice 6; signal honoring through phase-runner
   → llm-caller → LLM plugins is handed to Slice 8 (best-effort termination in the interim).

4. **`max_active_duration_ms` enforcement: terminate → failed + alert** (D4). Subscribe to the
   existing `health.stuck_detected` event with `condition: "no_state_transition"`. Wall-clock
   from `started_at` (blocked time counts). Stuck-staleness threshold stays warn-only.

5. **Crash recovery unification** (D5). Both boot recovery and per-task crash flow through
   `retryPolicy.recordFailure("crash", taskId)`. `consecutive_crash_count` carries across
   daemon restarts. Closes the boot-loop hole.

6. **Preemption: keep + tighten three things** (D6, refined by D13). Filter eligible candidates
   before picking. Bound `priority` to `[1, 100]` (research correction — matches DB CHECK).
   Document one-per-tick as deliberate policy. Force-preemption uses the terminate primitive.
   Dead `preemption.ready` event deleted. Dead `abandonPending` deleted.

7. **Eligibility surfacing: minimal cleanup, no new plumbing** (D7). With decomposition deleted,
   `isTaskEligible` is just a `not_before` check. Document the model in prose. No new events
   or queries.

8. **Phase-runner adopts retry-policy in Slice 6** (D8 — sub-decision to D3 split pattern).
   Avoids two writers on the new per-category counter fields in the interim.

9. **Cost-limit-queue adopts the terminate primitive in Slice 6** (D9). Notifications stay
   immediate from the queue; state transition becomes async via the terminate routing.

10. **`drainForShutdown` adopts the terminate primitive in Slice 6** (D10). Single shared
    timeout, not per-dispatch multiplication.

11. **Collapse `Outcomes.preempted` into `Outcomes.terminated`** (D11). Cooperative-vs-forced
    distinction in the reason field.

12. **`engineer retry` resets per-category counters** (D12). Owner intervention = fresh attempt.

13. **Add `failed → queued` transition** (D13, research refinement). Hard-cap victims must have
    a recovery path; `engineer retry` accepts failed tasks. Consistent with D12's philosophy.
