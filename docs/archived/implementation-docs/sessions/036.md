# Session 036 — 2026-03-10

## What Happened

Implemented Phase 4 (Event Bus) — the first Core component. In-process pub/sub with SQLite persistence to the `events` table. `EventBus` class supports typed publishing (compile-time payload safety via `PublishInput<T>`), glob-pattern subscriptions (`task.*`, `*`), replay for state reconstruction, and query methods. Created `createTestEventBus()` helper for all future phases. Resolved a contradiction between the build order ("validate payload against schema") and event-catalog.md L3 spec ("no runtime validation") — followed L3 as authoritative, documented runtime validation as a future consideration. 4 files created, 41 new tests, all verification passes (tsc, biome, vitest). Total: 469 tests across 12 test files.

## Decisions Made

1. **No runtime payload validation**: Follow event-catalog.md (L3 authoritative) over build order summary. Type safety via `PublishInput<T>` at compile time. Runtime validation documented in `future-considerations.md` for when third-party plugins can publish events.
2. **Bus generates timestamp**: Callers don't provide timestamp. Bus uses `new Date().toISOString()` at publish time. Tests use `vi.useFakeTimers()`. Delta between action time and publish time is negligible for audit.
3. **`console.error` for subscriber failures**: No pino dependency injected. EventBus is low-level Core — keeps constructor simple. Can be wrapped or redirected later.
4. **Glob pattern semantics**: `"*"` matches any event type. `"task.*"` matches exactly two segments where first is `task`. Segment count must match.
5. **`vitest.config.ts` expanded**: Added `test/helpers/**/*.test.ts` to unit test include patterns, alongside existing `src/**/*.test.ts` and `test/boundary/**/*.test.ts`.
