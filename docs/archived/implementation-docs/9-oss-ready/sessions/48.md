## Decisions Made

All surfaced to Farzam up front; he took every recommendation.

1. **Gap-fill + relocate, not a literal port.** Treat §15 as a candidate list, not a mandate: add only
   principles that fill a real gap and generalize; merge overlaps; move structural code principles to
   `coding-standards.md`. A literal port would have duplicated existing principles, bloated the prompts,
   and dragged in interactive-session prescriptions that do not fit an autonomous batched agent.
2. **No prompt-content / hardcoded-string tests.** Killed the `describe("prompt")` blocks across the
   prompts (Farzam's mid-session steer, consistent with the testing philosophy). Prompt wording is
   judgment to shape, not a string contract to snapshot.
3. **Skip refactor-guide "visible staleness beats silent staleness"** — substantially overlaps Fail Loud
   + §15 graceful-degradation logging; adding it risks the duplicate-principle overlap the merge rule
   warns against.
4. **The two structural principles live in coding-standards, not self-review** — encode-contracts-in-code
   and isolated-failure-boundaries benefit every phase (the agent grounds in the standards), so the
   standards are their home; self-review keeps only the lens-specific keep-on-sight counterweight.
