# Session 56 — 2026-06-02

## What Happened

A **cross-cutting deep refinement pass — not a feature slice** — across the existing code along two
lenses: radical observability (the headline) and code quality vs `coding-standards` / `anti-patterns` /
`philosophy`. It targeted the observability-critical core (the per-task pipeline, the daemon, the
orchestrator, the observer plumbing, the safety layer) plus the observation-type vocabulary end to end
(schema → Core emitters → dashboard). It goes *deeper* than the Slice-8 observability audit (`d51b048`,
which instrumented the pipeline spine) and catches what that pass left untouched.

Run as a **multi-agent orchestration** (ultracode): a parallel read-only audit (four agents, one per
tier) produced a consolidated, prioritized findings inventory (`.claude/temp/audit/observability-and-quality.md`,
33 findings, 9 high); a parallel refactor across **four file-disjoint lanes in isolated git worktrees**
landed the agreed fixes green-on-commit; a three-agent **adversarial review** then verified the integrated
diff; and the orchestrator (Claude, hand-driven) made every review-driven fix and verified the whole
thing first-hand. All work is on branch **`s56-refinement`** (six commits, not merged to `main` at wrap).

The core was already well built — the audit confirmed the pipeline spine, the FCIS purity of
policy-engine, span idempotency, blob dedup, and sanitization are genuinely sound — so the work was
wiring built-but-unused observability, cutting dead surface, and a handful of real defects the
adversarial pass surfaced that a green gate could not.

## Decisions Made

1. **`cost_snapshot` → CUT** (Farzam). Cost is already observable via `cost.incurred` events, the
   `tasks.agent_cost_usd` column, and the new per-phase aggregation; a periodic snapshot would be a
   second cost source that can drift. A spend-over-time curve view is left for Slice 13 if wanted.
2. **The autonomy / `should_i_ask` engine → RESERVE for Slice 10, not cut** (Farzam). `evaluateAutonomy`
   + `findRepoOverride` + the `autonomy_policy` emission are fully built but unwired — the only live
   `consultJudgment` path is `cost_check`. It is a real configured feature (autonomy levels) that
   Communication/Slice 10 will wire. Kept intact with reserved-scaffolding comments at the call sites
   so it is never mistaken for live.
3. **Default lean = WIRE, cut only genuine residue** (maximal-observability lens). Wire `push`,
   `create-pr`, `workspace_op`, `quota_status`, and per-phase cost (data exists, no adapter-contract
   change). Cut `config_change` (hot-reload deleted in Slice 5), `agent_iteration` (the agent loops in
   an opaque subprocess Core cannot observe), and the dead pub/sub + error surfaces.
4. **`quota_status` wiring needs no adapter change** — `getQuotaStatus()` is already on the
   `AgentAdapter` contract and implemented by plugins; the plugin-opacity invariant is untouched.

## What Landed

**Wired (lit up invisible/empty observability):**
- `push` (`git_push`) and `create-pr` (`create_pr`, `dismiss_approvals`) now emit `tool_execution`
  spans; `pr-manager`'s `remove_thoughts_and_push` retyped from `plugin_call` to `tool_execution`.
- `workspace_op` now emitted by the WorkspaceManager for worktree create/cleanup and branch delete —
  the dashboard's previously-empty "Workspace" filter has data.
- `quota_status` emitted by a slow-cadence daemon poll (every 20 ticks) via `getQuotaStatus()`.
- Per-phase cost + agent-call count now real: the `agent_call` span carries `cost_usd` / `tokens_in` /
  `tokens_out` / `cache_read_tokens`, and the dashboard derives `/cost`, `/phases`, and the system-bar
  total from a single `agent-cost-aggregation` module (killing the always-zero "N agent calls" and the
  empty per-phase cost the phantom `phase_transition` field reads produced).
- Self-unblock is now a `recordDecision` (auto_resolve vs escalate, carrying the agent's reasoning);
  task pickup anchored as a `lifecycle` observation under the root span.

**Cut (dead surface / honest vocabulary):**
- The entire in-process `ObserverStream` pub/sub — zero production consumers (the dashboard SSE polls
  SQLite by rowid across a separate process, so an in-process subscriber could never reach it).
- `safety-layer/errors.ts` (four throw-classes; the layer is deliberately deny-don't-throw), the
  public `getCostStatus` (kept on `ICostTracker`), `BlobStore.exists()`, the unread
  `OrchestratorContext.observationStore` field, a stale "13 observation types" comment.
- Three never-emitted observation types from the schema + client mirror: `config_change`,
  `agent_iteration`, `cost_snapshot`. Added the emitted-but-missing `task_execution` to the client.
- `TracedObserver` folded into `Observer` (optional `traceId`), removing ~100 duplicated lines **and**
  fixing a latent shallow-ctx hazard (traced children now share the root context by reference, so a late
  `observer.upgrade(store)` reaches them).

**Adversarial-review fixes (hand-done, commit `0f9fca9`):**
- The quota widget read `used`/`limit` (never on the `QuotaStatus` contract) → permanent wrong 0% bar;
  rewritten to render the real `windows[]` (`used_percentage`, exhaustion, rate-limited badge).
- `cache_read` threaded onto the `agent_call` span (the "Cache Read" total was reading an unwritten field).
- `totalSpend` given honest null-when-no-numeric-cost semantics, rendered as "—" (not `$0.00`) in the
  system bar; `aggregateAgentCost` made the single cost source (deleted the duplicate `totalAgentSpend`).
- `recordError` forces level `error` even if a caller passes `opts.level` (the redundant-level cleanup
  had introduced a latent downgrade path).
- Added direct tests: the cost aggregator, the `recordError` level floor, the pino trace bindings, and
  the quota-poll cadence + error paths.
