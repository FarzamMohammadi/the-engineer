## What Happened

- **Task 1.1 + 1.5 — config-version machinery (`3c5b2b5`).** Deleted `CURRENT_CONFIG_VERSION`,
  `ConfigVersionSchema`, `ConfigVersion`, `detectConfigVersion`, the version-mismatch warning,
  and the `version` field on `ConfigBundle`. Verified zero consumers — `detectConfigVersion`
  always returned `1` (no template ever writes `version:`). Recorded the decision in
  `future-considerations.md`: one latest schema per config file today; explicit schema
  versioning with migrations is the post-v1 option.
- **Task 1.2 — `checkCliArtifacts` (`fe849af`).** Removed the doctor check that scanned
  `~/.claude/projects/` — a Plugin Blindness violation (hardcodes one LLM plugin's on-disk
  layout) that was informational-only with near-zero value. Doctor now runs 8 unconditional
  checks + 1 conditional (risky config). The `cli.md` category table already matched this.
- **Task 1.3 — `Output.table()` + `"quiet"` mode (`0fefb11`).** Deleted the unused `table()`
  method and the `"quiet"` `OutputMode`, which the CLI never selected (only `--json` exists).
  `status.test.ts` and `doctor.test.ts` had relied on `"quiet"` to silence output — switched
  to mocked stdout/stderr and `"json"` respectively.
- **Task 1.4 — consolidation, double scan, `getNumberPaths` (`d5b5bb9`).** Extracted the
  duplicated `checkRequirementsMet` into a new leaf module `src/cli/setup/requirements.ts`;
  fixed `start.ts` scanning the config dir twice (scan once, pass to both consumers);
  dropped the `export` on `getNumberPaths` (internal helper of `parseDurations`).

## Decisions

1. **`checkRequirementsMet` extracted to its own file, not imported from `setup.ts`.** The
   plan said `prompts.ts` should import it from `setup.ts` — but `setup.ts` already
   lazy-imports `prompts.ts` (to defer loading `@inquirer/prompts`), so that closes a cycle
   `madge` flags. Owner chose the professional fix: sink the pure helper to a leaf module
   `src/cli/setup/requirements.ts` that both depend on. The cycle was the codebase saying
   the function was at the wrong layer — fixed structurally, not suppressed. Tests moved to
   a mirroring `requirements.test.ts`.
2. **`getNumberPaths` direct tests removed with the export.** Privatizing the function
   broke its 9 direct unit tests (white-box tests of the schema-walk tree). The behavior
   stays covered by the `parseDurations` tests + `loadConfig` integration tests — testing a
   private implementation detail directly is the kind of test the project's testing
   philosophy says to drop.
