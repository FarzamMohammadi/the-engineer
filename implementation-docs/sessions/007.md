# Session 007 -- 2026-03-07

## What Happened

Designed Session/Memory -- second Layer 2 component, resolving 3 gaps (#2, #7, #21). Key insight: Session/Memory stores the agent's working context and learned knowledge, complementary to Task Engine (status) and Event Bus (raw events). Three proven systems inform the design: WAL, journaling filesystems, and content-addressable storage.

## Decisions Made

1. **Context reconstruction over conversation replay** -- resume from compressed checkpoint summaries, not LLM conversation replay. Fast, cheap, deterministic. Summary quality is an Orchestrator concern.
2. **Two knowledge scopes: repo + user** -- repo-scope isolated per repository (conventions, patterns, domain). User-scope for learned personal preferences across all repos. Precedence: Repo > User > Defaults.
3. **Learned vs declared knowledge** -- knowledge is dynamic (observed over time). Config is static (explicitly set). User-scope knowledge is what the Engineer discovers about the user, not what the user configures.
4. **Session Journal as curated narrative** -- separate from Event Bus. Journal captures Orchestrator's human-readable reasoning. Event Bus captures exhaustive system events. Different granularity, different audience, complementary data.
5. **Dashboard vision** -- Event Bus + Journal + Task history as data foundation for a comprehensive Engineer Dashboard showing everything past, present, and live.
