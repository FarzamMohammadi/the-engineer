## Decisions Made

1. **Wipe HookRegistry entirely** — not just exclude it from PluginContext. It had no producers or
   consumers anywhere; speculative scaffolding, deleted (−387 net). Future hooks get designed against real
   requirements.
2. **Per-plugin logger via `observer.childPlugin(id)`**, not the plan's literal `observer.child(manifest.id)`
   — the latter doesn't fit the closed `ComponentTag` union. `childPlugin` binds `plugin_id` as structured
   data + `component: "plugin"`, Core-stamped (queryable, unforgeable by normal use). Added `"plugin"` tag,
   removed dead `"hooks"` tag.
3. **PluginContext = `{ logger, stateStore }`** (two members) — no `hookRegistry` after the deletion.
   `manifest` stays separate (identity vs capabilities). `context` is required (`!`), not optional — a
   missing context now fails loud instead of silently skipping logs.
4. **Registry takes a `createStateStore(pluginId)` factory**, not the DB — keeps the Registry decoupled
   from persistence/SQLite; trivially fakeable in tests.
5. **Panel refinements folded into the plan**: index/query `idempotency_key` alone (keys are globally
   unique by convention); StateStore methods throw → lifecycle catches; `get` returns `unknown|null`;
   dedup round-trip test added to the verification contract.
6. **Tests inject context exactly as they inject manifest** — new `createTestPluginContext` /
   `createTestStateStoreFactory` helpers; the Registry sets both together, so tests bypassing the Registry
   set both.
