## Decisions Made

1. **Vocabulary union types are re-exported from `types/api.ts`.** The const member values live in one
   module (`lib/vocabulary.ts`, parity-tested); `types/api.ts` re-exports the unions so every consumer keeps
   importing contract types from one place and `constants.ts` sources `PHASE_ORDER` from `PHASES`.
2. **`pending_pr_event` typed as `string | null`, not a full enum union.** S1's parity test scope is the 5
   enums the spec named; `PrEventType` is out of scope, so the client types the raw value without expanding
   the parity surface. Promote to a parity-tested union if/when a view needs to switch on it.
3. **`blocked-response.tsx` got the minimum S1 cleanup, not the S3 rebuild.** Deleting reads of fields that
   never exist (`question`/`context`) and accepting the typed prop is honest S1 work; the legible
   category/sub_phase/reason rendering with `needed` as the headline is explicitly S3.
4. **`phases_ran` validates against the real phase set and de-dups.** A stale/garbage value in `input.phase`
   (the exact drift that produced `self_review`) is dropped rather than surfaced — the list shows only
   genuine phases the task ran.
