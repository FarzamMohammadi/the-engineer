## Decisions Made
1. **`block_reason` is a new list field, distinct from `blocked_reason`.** The existing `blocked_reason` is the
   free-text latest-transition reason (used in the blocked card). The block-reason *filter* needs the closed
   `BlockReason` enum, which lives in the `blocked` payload — so the API now parses and exposes it separately rather
   than overloading the free-text field. Honest source, no display regression.
2. **Sub-phase/loop affordance on list rows is gated to in-flight tasks.** `sub_phase`/`phase_iteration`/
   `total_reworks` describe the *current* phase; on a terminal task they are stale, so `PhaseCell` passes them only
   when the task is active or blocked.
3. **`block_reason` parsed from the `blocked` payload, not derived from the state-transition reason.** The coarse
   enum the daemon routes on is authoritative in `blocked.reason`; the state-transition `reason` is human prose. The
   filter switches on the enum.
4. **`__APP_VERSION__` keeps the established Vite double-underscore convention** (with a targeted `biome-ignore` for
   `useNamingConvention`) rather than being renamed — the `__NAME__` form signals "compile-time injected global, not
   a real variable", the standard for bundler defines.
5. **The reaper event publishes in the `finally`, after `lastRun` is set.** It fires on every sweep — including ones
   where per-task reaps failed — so the dashboard's failed count is truthful, mirroring data-lifecycle.
