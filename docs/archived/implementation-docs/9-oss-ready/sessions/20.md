## Decisions Made

1. **`poll_interval_ms` lives top-level on `PluginManifestSchema`** (optional numeric), not in
   `adapter_meta`. One optional field, discoverable, usable by any future poller; minor widening of
   the universal manifest is acceptable.
2. **`event_type` is the static `"issue"`** — the match criteria (label/assignee) is a config
   concern, not an event classification. Simpler and more honest than a dynamic per-match string.
3. **`labels` defaults to `["engineer"]`** (overrides the plan's D7 "reject neither, no default").
   Frictionless defaults beat a fail-loud wall — aligns with the philosophy "defaults handle
   everything, friction is zero." The Zod guard remains but now only fires on an *explicit*
   `labels: []` with no assignee — the deliberate match-everything footgun. Recorded as an
   implementation refinement on slice 05 decision #6.
4. **Rate-limits do not count toward consecutive failures.** A 429 is transient and self-resolving;
   the daemon honors `retry_after_ms`, sets a per-plugin deadline, and clears it on success. Only
   opaque/non-rate-limit errors increment the failure counter and feed exponential backoff.
5. **Dashboard SPA path follows the migrations convention** —
   `resolve(import.meta.dirname, "dashboard")` (co-located with the bundled entry at
   `dist/index.mjs`), not the source-tree-relative `../../dist/dashboard`. Fixes prod (`:3847`);
   dev keeps the vite HMR server on `:5173` (per the existing CORS allow-list).
6. **Closed all four config-generation paths**, not just the user's seed: interactive
   `promptForConfig` reverted to repo-only (default covers selection), `templates.ts` (active +
   reference) fixed (also corrected a latent bug where `labels` was wrongly nested under `repos[]`
   and removed the dead `poll_interval` line), and both seed files updated.
