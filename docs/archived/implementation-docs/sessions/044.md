### Key Design Decisions

- **Factory function** (`createDaemon()`), not class — consistent with Decision #124
- **Fire-and-forget dispatch**: `orchestrator.executeTask()` returns Promise, handled via `.then()/.catch()` — tick loop never blocks on long-running tasks
- **Concurrency-ready**: `max_concurrent` config + `activeDispatches` Map — multi-core via config change, never hardcoded boolean
- **Injectable Clock**: `FakeClock` for deterministic tests, `RealClock` for production — no timer mocking needed since tick loop is manually driven
- **Cooperative preemption**: Daemon requests → Orchestrator yields between phases → swap on next tick
- **Priority aging**: starvation prevention with configurable threshold/increment/interval/cap
- **PID file**: single-instance enforcement via `{engineerHome}/run/engineer.pid` with stale detection

### Tick Loop (7 Steps)

1. Process event-driven flags (cost limits)
2. Poll triggers (with dedup via `seenTriggerKeys` TTL map)
3. Evaluate preemption (priority delta threshold)
4. Schedule (highest-priority queued task to available slot)
5. Priority aging (bump stale queued tasks)
6. Stuck detection (emit health events)
7. Cleanup expired seen keys
