## Decisions Made

1. **Reconciliation reaper** (over event-driven / minimal-cut) — forced by timer-based retention +
   cross-process cancel; idempotent/crash-safe (the stateless philosophy Slice 8 established). (D1)
2. **Reaper is the sole branch deleter**; `auto-merge` only records the merge (`merged_at` + audit +
   self-merge milestone; external-merge backfill is audit-only). (D2, D10)
3. **Single `branch_retention_days`** (`null`=keep / `0`=next sweep / `N`=days; default `0`,
   `.nonnegative()`); `delete_branch_after_merge` deleted; `CleanupConfig` cut entirely. (D3, D8)
4. **Distinct `cancelled` terminal state** (mechanical fork: reap-vs-preserve, retry-vs-not), with a
   `TERMINAL_STATES`/`isTerminal()` SSOT collapsing 4 ad-hoc predicate sites. Failed tasks untouched
   by the reaper. (D4, D5, D9, D13)
5. **Effective cross-process cancel** — guarded *versioned* cancel writes (dashboard + new
   `engineer cancel` CLI); active tasks aborted via Slice 6's terminate machinery (`user_cancelled`,
   early-return no re-transition). (D6, D11, D14)
6. **Cancel-with-open-PR closes the PR** (wiring dead `closePR`); first to cut if Session 3 runs hot. (D12)
7. **Separate `workspace-reaper` service** built inside `createDaemon` (needs `dispatchTracker`). (D7)
8. **Panel-forced corrections:** `reaped_at` all-or-nothing marker is the reconciliation lynchpin
   (the original "clear the workspace pointer" had no implementation) (D16); `merged_at` stamped with
   `new Date()` not `clock.now()` (no clock on the orchestrator context) (D15); cancel writes must bump
   `version` to serialize with the daemon's CAS (D14); a full reaper failure envelope + `getLastRun()`
   observability (D17). The e2e real-INSERT dedup test (both app `NOT IN` + DB index `:83`) is the
   single most important test.
9. **Process:** docs ride with each implementation session (DoD item 7) → 5 sessions collapsed to 4
   (state-model spine → reaper+auto-merge → cancel → narrative+sweep).
10. **Methodology note:** the "no sub-agents" rule is about routine research delegation; the
    expert-panel stress-test (and large audits/sweeps) are part of the RRP methodology and do use
    sub-agents — Farzam approved running the panel.
