## Decisions Made

1. **Drop the `code` sub_state entirely (not keep it as the pr_review_pending discriminator).** `checkPermission` is consumed only by the agent action-pipeline, and agents never run in `blocked`/`review_pending` — so review_pending's conditional merge permission was already dead. Discriminate blocked tasks by `reason` (per the locked design), making `code` orphaned → removed.
2. **`checkBlockedEscalation` excludes `pr_review_pending` now (a forced D11 fragment).** Without it, a PR sitting in review would be swept into the escalation ladder → self-unblock agent runs → marked `failed`. Behavior-preserving: review_pending and blocked were disjoint before and stay disjoint by reason. The deeper D11 semantic audit (response-poller, unblock-resolver nuance) still defers to Session 7.
3. **`BlockReasonSchema` = today's four reasons only.** No forward-looking values (vestigial until Session 2+ emits them).
4. **Deleted unblock-resolver's `reason: ""` placeholder.** Verified the preserved `contacted` history was dead (only re-read to re-persist itself). On unblock → `blocked: null`. Enum-safe and aligned with strict-data-invariants.
5. **Kept the satellite names** `NotificationKinds.review_pending` and `response_timeout.review_pending` (a notification kind and a policy key, not a state; renaming is Slice 10 scope); merged `SessionEndReasons.review_pending` into the existing `blocked`.
6. **Deferred `BlockDetail` + `FailureCategory` to Session 2.** Unconsumed in Session 1 and would reference an undefined `FailureCategory`; lands with `cli-run` that produces it. `BlockReasonSchema` (consumed now) did land.
7. **Removed dead `child_pr_strategy` fully** (schema + templates + docs), not just the doc row — zero readers since decomposition left.
