# Session 009 -- 2026-03-08

## What Happened

Designed Safety Layer -- fourth Layer 2 component, resolving 3 gaps (#5, #17, #19). The Safety Layer is the policy enforcement authority: stateless evaluator derived from SELinux/IAM and circuit breaker patterns. Key insight from Farzam: LLM providers come in two fundamentally different cost models (CLI subscription-based vs API pay-per-token) and both must be accommodated.

## Decisions Made

1. **Safety Layer derives from SELinux/IAM** -- stateless policy evaluator, deny-by-default for dangerous operations. Does not query other components; state flows to it via Event Bus events.
2. **Cost accumulators internal to Safety Layer** -- subscribes to Event Bus cost events, maintains ephemeral accumulators (reconstructable from Event Bus history). Two independent cost views: per-task (Task Engine) and cross-task aggregates (Safety Layer).
3. **Two LLM provider types** -- CLI-based (Claude Code, Gemini CLI, Codex) with subscription limits vs API-based (OpenRouter, direct keys) with dollar budgets. Different cost semantics, shared Safety Layer interface.
4. **Cost limit = stop** -- no graduated wind-down. When limit hit: checkpoint, block task, notify human, wait for reset or budget increase. Simple and predictable.
5. **Response timeout: Safety owns policy, Daemon executes** -- single source of truth for timeout stages. Daemon reads thresholds from Safety config.
6. **Autonomy by decision category** -- configurable categories (architectural, refactoring, dependencies, etc.) mapped to three levels (always_ask, threshold, always_decide). Per-repo overrides supported.
7. **Self-unblock respects autonomy** -- always_ask categories cannot self-unblock regardless of wait time.
8. **Active interceptor: veto-only** -- never modifies events. Vetoed events still logged for audit trail.

## Key Design Elements

- Dual mode: active interceptor (Event Bus pre-processing hook, veto-only) + passive consultation (three-way verdict: proceed/ask_human/deny)
- Two-model cost tracking: CLI subscriptions + API budgets
- Cost accumulators ephemeral, reconstructable from Event Bus (same pattern as Daemon)
- Scope boundaries: repos, branches, files, external domains
- 10 default autonomy decision categories, all user-configurable
- Response timeout: 3 stages for Blocked (reminder/self-unblock/alert), reminder-only for Review-Pending
- Config layering: Global defaults > User config > Per-repo overrides
