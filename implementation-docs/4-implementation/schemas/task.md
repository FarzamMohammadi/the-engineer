# Task Domain Schemas

The Task is the primary unit of work. Source: [`../../2-components/task-engine.md`](../../2-components/task-engine.md).

**Persistence:** SQLite — `tasks` table + `state_transitions` table.

## ExternalRef

Links a task to its external source (GitHub issue, Jira ticket, etc.).

```typescript
const ExternalRefSchema = z.object({
  type: z.string(),                    // "github_issue", "jira_ticket", "manual"
  repo: z.string(),                    // "owner/repo"
  id: z.string(),                      // issue/ticket identifier (e.g., "42", "VE-123")
  url: z.string().optional(),          // link back to the external item
  pr_prefix: z.string().optional(),    // platform-formatted ticket ref for PR titles (e.g., "#42", "JIRA-123")
});
type ExternalRef = z.infer<typeof ExternalRefSchema>;
```

**Note:** `type` is an open string, not a fixed enum. New trigger sources can define their own types without schema changes.

**`pr_prefix`:** Set by trigger plugins to provide the platform-native ticket reference for PR title prefixing. Core prepends it to the PR title as an opaque string (e.g., `#42: Fix auth bug`). This enables platforms like GitHub to auto-link PRs to their originating issues. Plugin-blind — Core never inspects the prefix format.

## Task

The full Task schema. This is the largest type in the system.

```typescript
const TaskSchema = z.object({
  // --- Identity ---
  id: z.string(),                      // ULID
  external_ref: ExternalRefSchema.nullable(),

  // --- State ---
  state: TaskStateSchema,
  sub_state: SubStateSchema.nullable(),
  phase: z.string().nullable(),        // Orchestrator phase: "research", "planning", etc.

  // --- Hierarchy ---
  parent_id: z.string().nullable(),
  children: z.array(ChildEntrySchema),
  cascade_policy: CascadePolicySchema,

  // --- Context ---
  title: z.string(),
  description: z.string(),
  source_text: z.string(),            // original issue/ticket body, preserved verbatim
  acceptance_criteria: z.array(z.string()),
  team: z.array(TeamMemberSchema),
  related: z.array(RelatedItemSchema),
  decisions: z.array(TaskDecisionSchema),
  child_summaries: z.array(ChildCompletionSummarySchema),

  // --- Workspace ---
  workspace: TaskWorkspaceSchema.nullable(),

  // --- Review ---
  review: ReviewStateSchema.nullable(),

  // --- Blocked ---
  blocked: BlockedDetailsSchema.nullable(),

  // --- Tracking ---
  priority: z.number().int(),         // 1-100, higher = more important
  llm_tokens: z.number().int(),       // cumulative — real column, not JSON
  llm_cost_usd: z.number(),           // cumulative — real column
  compute_time_ms: z.number().int(),  // cumulative — real column

  // --- Timestamps ---
  created_at: z.string().datetime(),
  started_at: z.string().datetime().nullable(),     // first time entering Active
  completed_at: z.string().datetime().nullable(),
  last_transition_at: z.string().datetime(),

  // --- Session link ---
  session_id: z.string().nullable(),  // ULID, links to most recent Session
});
type Task = z.infer<typeof TaskSchema>;
```

### SQLite Storage Notes

| Field | SQLite Column Type | Notes |
|-------|-------------------|-------|
| `id` | TEXT PRIMARY KEY | ULID |
| `state`, `sub_state`, `phase` | TEXT | Real columns — queried/filtered |
| `parent_id`, `session_id` | TEXT | Foreign keys, indexed |
| `title`, `description`, `source_text` | TEXT | Real columns |
| `cascade_policy` | TEXT | Enum value |
| `priority` | INTEGER | Sorted by scheduler |
| `llm_tokens`, `compute_time_ms` | INTEGER | Real columns — hot-path counters |
| `llm_cost_usd` | REAL | Real column — hot-path counter |
| `external_ref` | TEXT (JSON) | `json_extract()` if needed |
| `children`, `team`, `related`, `decisions`, `child_summaries`, `acceptance_criteria` | TEXT (JSON) | JSON arrays, always loaded with task |
| `workspace`, `review`, `blocked` | TEXT (JSON) | JSON objects, nullable |
| `created_at`, `started_at`, `completed_at`, `last_transition_at` | TEXT | ISO 8601 |

### What's NOT on the Task Object

**`history` (StateTransition[]):** L2 defined `history: StateTransition[]` on the Task. In the concrete implementation, state transitions live in a **separate `state_transitions` table** — not embedded on the task. This enables cross-task audit queries (`SELECT * FROM state_transitions WHERE to_state = 'blocked'`). To get a task's history: `SELECT * FROM state_transitions WHERE task_id = ? ORDER BY timestamp`.

## StateTransition

Append-only audit trail. Every state change is recorded.

```typescript
const StateTransitionSchema = z.object({
  id: z.string(),                      // ULID
  task_id: z.string(),                 // FK to tasks
  from_state: TaskStateSchema,
  to_state: TaskStateSchema,
  from_sub: SubStateSchema.nullable(),
  to_sub: SubStateSchema.nullable(),
  reason: z.string(),
  timestamp: z.string().datetime(),
  triggered_by: z.string(),           // component or event ID that caused this
});
type StateTransition = z.infer<typeof StateTransitionSchema>;
```

```typescript
const ValidTransitions: Array<{

  from_sub?: SubState;
  to: TaskState;
  to_sub?: SubState;
}> = [
  { from: "intake", to: "queued" },
  { from: "intake", to: "failed" },
  { from: "queued", to: "active", to_sub: "working" },
  { from: "active", from_sub: "working", to: "blocked" },
  { from: "active", from_sub: "working", to: "review_pending", to_sub: "demo" },
  { from: "active", from_sub: "working", to: "review_pending", to_sub: "code" },
  { from: "active", from_sub: "working", to: "completed" },
  { from: "active", from_sub: "working", to: "failed" },
  { from: "active", from_sub: "working", to: "queued" },                         // preemption
  { from: "active", from_sub: "working", to: "active", to_sub: "supervising" },
  { from: "active", from_sub: "supervising", to: "active", to_sub: "working" },  // merge conflict
  { from: "active", from_sub: "supervising", to: "blocked" },
  { from: "active", from_sub: "supervising", to: "active", to_sub: "integrating" },
  { from: "active", from_sub: "supervising", to: "failed" },                     // cascade fail-fast
  { from: "active", from_sub: "integrating", to: "review_pending", to_sub: "demo" },
  { from: "active", from_sub: "integrating", to: "review_pending", to_sub: "code" },
  { from: "active", from_sub: "integrating", to: "completed" },
  { from: "active", from_sub: "integrating", to: "failed" },
  { from: "blocked", to: "active", to_sub: "working" },
  { from: "blocked", to: "active", to_sub: "supervising" },
  { from: "blocked", to: "failed" },
  { from: "review_pending", from_sub: "demo", to: "active", to_sub: "working" },
  { from: "review_pending", from_sub: "demo", to: "review_pending", to_sub: "code" },
  { from: "review_pending", from_sub: "code", to: "active", to_sub: "working" },
  { from: "review_pending", from_sub: "code", to: "completed" },
];
```

This table can serve as runtime validation data — `requestTransition()` checks the transition against this list before allowing it.

## Permission Table

The state machine as a permission gate. Maps `(state, sub_state)` to allowed action classes.

```typescript
type PermissionEntry = {
  state: TaskState;
  sub_state: SubState | null;
  allowed: ActionClass[];
  conditional?: Partial<Record<ActionClass, string>>; // condition description
};

const PermissionTable: PermissionEntry[] = [
  { state: "intake",         sub_state: null,           allowed: ["read"] },
  { state: "queued",         sub_state: null,           allowed: ["read"] },
  { state: "active",         sub_state: "working",      allowed: ["read", "write", "test", "git_local", "git_remote", "communicate", "task_manage", "ask_human"] },
  { state: "active",         sub_state: "supervising",  allowed: ["read", "communicate", "task_manage", "ask_human"] },
  { state: "active",         sub_state: "integrating",  allowed: ["read", "write", "test", "git_local", "git_remote", "communicate", "ask_human"] },
  { state: "review_pending", sub_state: "demo",         allowed: ["read", "communicate"] },
  { state: "review_pending", sub_state: "code",         allowed: ["read", "communicate"], conditional: { merge: "auto_merge configured for repo" } },
  { state: "blocked",        sub_state: null,           allowed: ["read", "communicate", "ask_human"] },
  { state: "completed",      sub_state: null,           allowed: [] },
  { state: "failed",         sub_state: null,           allowed: ["communicate"] }, // failure notification only
];
```
