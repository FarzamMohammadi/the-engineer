## Decisions Made

1. **Event Bus down = system halt** (#53) — If Event Bus storage becomes inaccessible mid-operation, system halts. Audit trail is a safety requirement. Checkpoint active tasks, stop new work, alert human.
2. **LLM provider auto-failover** (#54) — Daemon switches to next provider in configured priority list on failure. Task continues, cost tracking updates, human notified of switch.
3. **Comm plugin fallback chains** (#55) — People Directory `contacts[]` is an ordered list per person. System tries channels in order. Resolves plugin-contracts.md open question.
4. **Config reload failure triggers health alert** (#56) — Failed hot-reload emits `health.config_reload_failed` event. Component keeps previous valid config. Human alerted.
5. **Checkpoint without LLM** (#57) — Minimal checkpoint (phase, workspace state, raw data) when LLM is unavailable. No narrative `context_summary`. Degraded but resumable.
6. **GitHub state reconciliation on recovery** (#58) — Automatic reconciliation when GitHub comm plugin recovers from outage. Runs once, not continuously.

## Error Propagation Chains Documented

1. LLM Provider Down — auto-failover or stuck detection
2. Event Bus Down Mid-Operation — system halt
3. Comm Plugin Failure During Blocking — timeout ladder + fallback channels
4. Checkpoint Storage Failure — context-dependent (phase transition, preemption, cost limit, shutdown)
5. Cascade Failure in Task Hierarchy — recursive policy application through tree
6. Workspace / Git Failure — varied by failure type
7. Config Hot-Reload Failure — keep previous, alert human

## Recovery Patterns Named

1. Checkpoint-then-fail — preserve context before Blocked/Failed
2. Retry-with-backoff — transient external failures
3. Fallback-channel — alternative comm paths
4. Ephemeral-reconstruction — rebuild from persistent stores
5. Degrade-and-continue — reduced capability with notification
6. Graceful-halt — safe shutdown when critical failure
