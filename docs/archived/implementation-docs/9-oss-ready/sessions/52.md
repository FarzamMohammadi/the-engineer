## Decisions Made

1. **`status.ts` is the 5th terminal-predicate site** (research missed it). Its default-hide
   `WHERE state NOT IN (…)` and `CASE` ordering would have leaked cancelled tasks into the default
   `engineer status` view. Derived the clause from `TERMINAL_STATES`; added `cancelled` to the CASE and
   the `--all` help text. In scope as correctness, not creep.
2. **Client `Record<TaskState>` maps are a compile necessity** (research missed it). Adding `cancelled`
   to the client union (which the plan puts in S1) breaks the dashboard **build** via three exhaustive
   `Record<TaskState,string>` maps. Gave them a minimal slate / "Cancelled" placeholder; the real
   chip/filter visuals stay Slice 13 per the deferral.
3. **Query-handler de-dup uses `TaskStateSchema.options`**, not the plan's `Object.values(TaskStates)`
   — `.options` is the precisely-typed `readonly TaskState[]` and iterating it directly removes both
   duplicated literal arrays with no intermediate const.
4. **`merged_at` written explicitly at the one full review literal** (`create-pr.ts`). tsc did not force
   it (`updateTaskField` takes `unknown`), but the row-mapper casts JSON without parsing, so an omitted
   field would read back `undefined`, not `null`. Explicit write keeps the round-trip sound for the S2
   reaper; the `...task.review` spread in `pr-event-poller` then preserves it.
5. **Nullable markers follow the codebase `.nullable().default(null)` convention** (required in the
   inferred type, passed explicitly at every construction site) — consistent with `not_before`,
   `pending_pr_event`, `accommodated_review_state`.
