## Decisions Made
1. **Model is task-level header context, no API change.** The `cost.incurred` events carry `model_id` but no
   span id, so a clean per-span join is impossible. Rather than mislabel each agent row's step as a model (the
   spec's explicit warning) or add a backend join keyed on nothing solid, the Agent tab fetches the task's
   `cost.incurred` events via the existing `useEvents` hook and shows the distinct models as header context.
   Honest and zero-backend-change.
2. **Phases-ran in detail derived from observations, not a new column.** The list endpoint computes
   `phases_ran`, but the detail endpoint does not. Instead of widening the detail API, the detail page derives
   the distinct real phases from the phase_transition observations it already fetches (`useTaskPhases`), via
   `readPhaseTransition` — the same `input.phase` source, kept in canonical pipeline order.
3. **Phase attribution uses the observation `phase` column for decisions/agent-calls.** route:/skip:/loop_*
   decisions and agent_call spans all carry the real phase in their `phase` column (set by the runner's
   `traceScope`), so the Phases tab attributes them by that column; phase_transitions group by `input.phase`
   per the spec. Both resolve to the same real phase.
4. **loop_repeat/loop_jump render as counters, not empty DecisionCards.** Those `decision_point` observations
   carry only `{ phase, count }` (no options/reasoning/confidence), so a DecisionCard would be an empty shell.
   They render as a compact "Repeated phase (×N)" / "Jumped back" line in the Phases tab and timeline instead.
5. **Overview cards split into sub-components.** The expanded overview render tripped a new biome cognitive-
   complexity warning; extracting each card (Blocked/Details/Cost/Timestamps/LastTransition/Criteria/Artifact)
   into its own function clears it and reads better — applied with judgment, not mechanically.
