## What Happened

### Requirements (Q&A)
- Goals, priority order: first-impression quality + OSS-grade code quality (tied), then
  simplification, then opportunistic resilience.
- Two personas: new user (guided, explicit confirmation) and power user (own seed, `reset.sh`).
- Getting-started path: `pnpm run setup` (install + build + link) → `engineer start`.
- OS detection gate: macOS continues, Linux warns + confirms, Windows blocks. macOS/Linux are
  POSIX-compatible; Windows out of scope for v1.
- Seed strategy (Option A): sanitize the tracked `seed-example/` to generic placeholders as a
  reference; personal seeds in gitignored `seed-example-*`; the team dogfoods the seed feature.
- Cross-cutting: never act on the user's behalf without asking; nice error handling everywhere.

### Research (`.claude/temp/research/slice-04-startup.md`)
- Full audit of all in-scope files — CLI entry, bootstrap, plugin loading, daemon startup,
  config, first-run setup.
- Findings: dead code (`Output.table()`, `"quiet"` mode, config-version machinery — verified
  zero consumers); a Plugin Blindness violation (`checkCliArtifacts` scans `~/.claude/projects/`);

  one developer's personal machine config; the Telegram `/start` handshake is built (its
