### New pure logic (unit-tested `.ts`, no DOM)
- **`client/src/lib/observation-shapes.ts`** — `readDecision`/`readVerdict`: narrow the opaque
  `Record<string,unknown>` `input` JSON into the exact `DecisionShape`/`VerdictShape` a component renders.
  The client can't re-validate with zod, so these drop malformed payloads to a safe partial/empty shape
  rather than throw (a single bad row must not white-screen the view). `readVerdict` never *infers* a pass
  from a missing flag and treats any failed gate as overriding a stray `passed:true`. The readers take a
  minimal structural `ObservationLike` (`{ type, input }`) rather than the full `Observation`, both so the
  test graph stays free of the client's extensionless-import chain (which only resolves under the client's
  `bundler` tsconfig, not the root/test NodeNext compiler) and because a reader has no business touching
  the rest of the row. Any `Observation` is structurally assignable.
- **`client/src/lib/blob.ts`** — `fetchBlob`/`isBlobRef` + a `BlobResult` union
  (`empty | loaded | not_found | error`). The blob endpoint returns raw *text* (not JSON) on 200 and a JSON
  404 body, so this bypasses `apiFetch` and uses `fetch` directly. An empty/malformed ref short-circuits to
  `empty` with no network call.

## Decisions Made
1. **Readers take `ObservationLike`, not `Observation`.** Keeps the testable `.ts` logic dependency-free for
   the NodeNext test compiler (the client's 66 extensionless relative imports only resolve under its own
   `bundler` tsconfig). Importing `types/api` pulled `types/api.ts` → `vocabulary.ts` into the test graph and
   tripped TS2835. A minimal structural slice is also the right abstraction — a reader shouldn't see the rest
   of the row. Did NOT add `.js` extensions to client source: that would break the project's consistent
   extensionless convention for the whole client.
2. **Components land ahead of their consumers; knip stays green by config, not by trivial wiring.** `knip.json`
   has `"ignore": ["src/dashboard/client/**"]` and `"project": ["src/**/*.ts"]` (not `.tsx`), so unused client
   exports are not flagged. Wiring is genuinely S3's unit of work (task-detail rebuild), so forcing a throwaway
   usage now would be churn. Flagged here so the next session knows the components are ready to consume.
3. **`async` onClick handlers rewritten to sync + `.then/.catch`.** Biome's `noVoid` rejects the
   `() => void asyncFn()` idiom; the handlers now kick off the promise and handle rejection inline, so the JSX
   handler stays `void`-returning and a clipboard/fetch failure degrades quietly.
4. **`readVerdict` is conservative about "passed".** Pass requires an explicit `passed:true` AND zero failed
   gates AND every gate passing — never inferred. A verdict is a safety signal; a false green is worse than a
   false red.
