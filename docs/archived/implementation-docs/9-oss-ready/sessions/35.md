## Decisions Made

1. **`cleanupWorkspace` leaves `task.workspace` intact.** No `cleaned_at` flag, no row nulling. The `workspace.cleaned` event is the canonical cleanup audit trail; the persisted workspace shape stays on the task row. Picked the plan's Option A after grounding: no caller today depends on null-post-cleanup (terminal-state tasks are never re-dispatched, and `triggerEvaluationIfEnabled` runs before cleanup in `handleCompletedOutcome`). The events table is the truth for cleanup history.

2. **WorkspaceManager constructor switches to an options object.** Adding `taskEngine: ITaskEngine` pushed the positional count from 4 → 5, past coding-standards § 3's "ideal 2-3, beyond that use options." 5 positional was a smell already; rather than add a 5th the next addition would force the refactor anyway. Introduced `WorkspaceManagerDeps` interface. Two construction sites updated (system.ts + test-workspace-manager.ts).

3. **`taskEngine.getTask` exceptions propagate out of workspace-manager reads.** No try/catch wrapping in `readRecord`. Per the Resilience lens this session: today's Map.get cannot throw, but DB reads can — and the plan explicitly required reads to fail loud, not silently return null on DB errors. Caller boundaries (scheduler dispatch, orchestrator main loop) already handle thrown errors via try/catch + observer; routing through them is strictly more informative than today's silent-null on bad state.

4. **`createWorkspace` owns the persistence write.** Plan scoped the `taskEngine.updateTaskField("workspace", ...)` call to `workspace-lifecycle.setupWorkspace`. Moved it into `WorkspaceManager.createWorkspace` itself instead: with the Map gone, "create the worktree" and "persist the workspace shape" become a single atomic contract. Callers can't forget the second step (foot-gun eliminated); tests don't need a manual updateTaskField after every create. The persistence write happens inside the method, immediately before the `workspace.created` event publish.

5. **Constructor takes `taskEngine: ITaskEngine` (not a narrower interface).** Considered defining a `IWorkspaceTaskAccess` shim with only `getTask` + `updateTaskField`. Rejected — the dep is small and concrete, the cost of a narrower interface (one more type to maintain, one more boundary) outweighs the boundary clarity gain. `ITaskEngine` is already the canonical task-engine contract; workspace-manager consumes a subset by usage, which is fine.

6. **Resume flow verification done via a focused unit test, not a new e2e.** Existing crash-recovery e2e already exercises the resume path end-to-end against the new shape; what was missing was an explicit assertion of the silent-bug-killer: "after restart, base_branch survives in `task.workspace` and a fresh WorkspaceManager reads it back." Added that via a focused unit test using the new `createWorkspaceManager()` helper. Adding a non-default-base e2e variant would require new test-repo setup; the focused unit test proves the contract without the cost.
