## Decisions Made

1. #119 — Three-tier Vitest configs: unit (`vitest.config.ts`), integration (`vitest.integration.config.ts`), e2e (`vitest.e2e.config.ts`). All use `pool: "forks"`. Shared base `vitest.shared.ts`. Pre-push runs unit only. Amendment to Decision #101.
2. #120 — Hybrid test directory: co-located unit tests (`*.test.ts` next to source), separate `test/` for integration, e2e, boundary tests, fixtures, and helpers. File naming: `*.test.ts`, `*.integration.test.ts`, `*.e2e.test.ts`.
3. #121 — Coverage strategy: `coverage.all: false`, 70/55 thresholds (lines/branches). Exclude CLI, daemon, plugins, wiring from coverage. Focus on schemas, state machines, adapters. Manual ratcheting. Adopted from OpenClaw.
4. #122 — Plugin contract compliance suites: one suite per adapter type, tests behavioral expectations TypeScript can't express (idempotency keys, error wrapping, usage reporting). Plugin authors run suites against their implementations.
5. #123 — Integration test strategy: real Core components + fake plugins. Registry is the primary testing seam. Shared immutable registry with fakes (adopted from OpenClaw). Fakes pass contract suites. In-memory SQLite per test.
6. #124 — E2E test approach: in-process daemon (`createDaemon()` returns controllable object), injectable clock (no real timers), 7 key scenarios mapped to Layer 3 lifecycle traces. All external dependencies faked.
7. #125 — Architectural boundary tests: verify three-tier import rules (plugins → SDK only, adapters → no plugins, core → no plugins). Adopted from OpenClaw's boundary enforcement pattern.
