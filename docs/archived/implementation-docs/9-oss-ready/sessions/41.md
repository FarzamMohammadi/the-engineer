## Decisions Made

1. **New phase names now, in the dark pipeline's own `Phase` enum** (`requirements/research/planning/execution/review/delivery`), coexisting with the legacy `PhaseSchema` until the S5 cutover. Folder-name coherence (`review/`, `delivery/`) wins; not a real dual-source-of-truth (two independent, coexisting pipelines). *(Farzam confirmed.)*
2. **Unified `BlockCategory` — refines the panel's D9.** *(Farzam's steer: "build a unified object that has all instead of second-guessing weird architecture.")* One complete cause enum covering failures **and** waits (`no_result`, `details_invalid`, `agent_failed`, `agent_unavailable`, `orchestrator_error`, `iteration_cap_hit`, `awaiting_human`, `awaiting_pr_review`) so every block carries one meaningful value and nothing is null. `BlockDetail = { category, sub_phase, needed }` (no stored `reason`); the coarse `BlockReason` is derived at the S5 wiring. `FailureCause` is the cli-produced subset (a derived `Extract`, not a second enum).
3. **`cli-run.ts` → `agent-step.ts` (`agentStep`)** *(Farzam's pick)* to kill the run/runner collision and the `run: cliRun(...)` stutter, and to use the agent-agnostic "agent" vocabulary. "CLI sub-phase" → "agent sub-phase" (the pair to "orchestrator sub-phase"). Folded into the core commit so history is clean. `runner.ts` kept.
4. **`agent-step` is scoped to the subprocess boundary only** (the slice's "dangerous 10% is one module"). Safety-pipeline gating, `cost.incurred` emission, and usage tracking are orchestration bookkeeping that wrap it at the cutover wiring — keeping the boundary clean and its tests free of that machinery.
5. **Runner shape:** every pipeline failure blocks *by construction* (the runner auto-blocks a `failed` result; `next` is only consulted for `ok`/`needs_human`); an abort re-throws (preemption — the caller checkpoints and resumes); a thrown orchestrator step → `block(orchestrator_error)`. Routing extracted to the pure `planRoute` (FCIS); one justified `biome-ignore` on the loop (cohesive cursor state machine, like the legacy loops); a `MAX_STEPS` backstop guards a cap-logic bug.
6. **Checkpoint counters ride in existing string fields during build-dark** — the typed `sub_phase` / `phase_iteration` / `total_reworks` columns and cross-dispatch counter persistence land at the S5 cutover (per the plan's deferral).
7. **Removed the `Phases` const export** (knip-unused while dark); S3 re-adds it as `pipeline.ts`'s first real consumer. Honest over tested-but-dead.
