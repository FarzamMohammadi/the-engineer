# Session 23 — 2026-03-09

## What Happened

Began Layer 4 (Implementation Design). Established the session plan: Layer 4 broken into 6 focused sessions (#23-#28), each tackling a related group of decisions. This session covered foundation technology choices.

Evaluated language options (TypeScript, Python, Go, Rust) — TypeScript won on type safety for our contract-heavy architecture. Researched OpenClaw (github.com/openclaw/openclaw), a similar TypeScript project with plugin system, multi-channel communication, and daemon architecture. Their stack (TypeScript, pnpm, Node 22, ESM, SQLite, Vitest, tsdown) validated several of our choices.

Discussed multi-threading and future scaling at length. Established guiding principle: every decision must work for v1 AND not block future evolution. SQLite behind interfaces is swappable — the storage adapter changes, Core doesn't.

Discussed cost constraints — polling over webhooks for v1, since GitHub API free tier is more than sufficient and avoids infrastructure costs.

## Decisions Made

1. #65 — TypeScript as primary language. Strong typing enforces L0-L3 contracts at compile time.
2. #66 — Node.js 22 LTS. Active support through Oct 2027.
3. #67 — pnpm as package manager. Fast, strict, workspace-ready.
4. #68 — ESM only. No CommonJS. Clean dynamic imports for plugins.
5. #69 — SQLite via better-sqlite3. Zero-config, embedded, behind interfaces for future swapping.
6. #70 — tsx (dev) + tsdown (production builds).
7. #71 — Biome for linting & formatting. Single Rust-based tool.
8. #72 — Zod for runtime validation. TypeScript-first, validates event payloads and configs.
9. #73 — Vitest for testing. Fast, TypeScript-native, multiple config support.
10. #74 — Polling-only triggers for v1. Zero cost, zero infrastructure. Webhooks later via TriggerAdapter.
