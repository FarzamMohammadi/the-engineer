# Session 008 -- 2026-03-07

## What Happened

Designed Daemon/Scheduler -- third Layer 2 component, resolving 2 gaps (#8, #12). The Daemon is the OS kernel scheduler of the system: manages what work gets done and when. Derived from single-core CPU with cooperative multitasking. Key tension resolved: single-agent philosophy vs parallel sub-tasks -- start single-core, design interfaces for future multi-core.

## Decisions Made

1. **Single-core CPU architecture, concurrency-ready** -- one Active.Working task at a time. All interfaces use abstract capacity (`max_concurrent` config, default 1). Multi-core is a future config change, not a redesign. Like Intel's path from single-core to multi-core.
2. **Graceful preemption only** -- agent finishes current atomic operation, checkpoints, then yields. Never interrupted mid-operation. Configurable preemption threshold (priority delta >= 20) prevents thrashing.
3. **User-assigned priority with defaults** -- scale 1-100, higher = more important. Explicit priority always wins. Defaults from task signals (bug → 70, feature → 50, critical → 90). Simple aging prevents starvation.
4. **Active.Supervising does not consume working slot** -- only Working and Integrating consume the agent's capacity. Supervising is lightweight monitoring. Enables parent-child execution on single core without deadlock.

## Key Design Elements

- Hybrid daemon loop: event-driven (Event Bus) + polling (triggers)
- Priority queue scheduling with FIFO tiebreak
- Graceful preemption flow: signal → finish atomic op → checkpoint → yield → swap
- Ephemeral daemon state: fully reconstructable from Task Engine on restart
- Dispatch package: full task + checkpoint (if resuming) + relevant knowledge
- Health monitoring: stuck detection, blocked timeout escalation, crash recovery
