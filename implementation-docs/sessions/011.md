# Session 011 -- 2026-03-08

## What Happened

Designed the Workspace Manager and Comm Plugins -- the final two Layer 2 components, resolving the last 3 gaps (#11, #20, #22). Layer 2 (Component Architecture) is now complete: all 7 components designed, all 24 gaps resolved, 38 total decisions made.

The Workspace Manager handles per-task git isolation using worktrees. Key innovation: progressive merge -- completed children merge into the parent branch immediately so dependent siblings get prior work's actual code. Multi-repo interface defined (primary/secondary model, same branch names across repos) with detailed mechanics deferred to Layer 3.

Comm Plugins design established two clean patterns: (1) comm plugins are dumb transport, Orchestrator owns all intelligence (query parsing, response composition, disambiguation); (2) GitHub state sync via Event Bus subscription (labels, milestone comments, child checklists).

## Decisions Made

1. **Git worktrees for task isolation** -- lightweight, share .git dir, natural fit for single-core. Worktrees are ephemeral; branches are persistent artifacts.
2. **Children branch from parent** -- namespaced: `engineer/{parent}/{child}-{slug}`. Hierarchy visible in branch names.
3. **Progressive merge** -- completed children merge into parent branch immediately (not deferred to Active.Integrating). Dependent siblings get prior siblings' actual code. Integration phase becomes lightweight.
4. **Multi-repo: interface now, details later** -- primary/secondary repo model, same branch name across repos, Task.workspace extended with `multi_repo` array. Cross-repo commit ordering and coordinated PR merge deferred to Layer 3.
5. **Comm plugins are transport, Orchestrator is intelligence** -- query parsing, response composition, notification cadence all live in Orchestrator. Swapping Telegram for Slack doesn't require reimplementing intelligence.
6. **GitHub state sync via Event Bus subscription** -- GitHub comm plugin subscribes to `task.state_changed` events. Syncs labels (`engineer:{state}`), milestone comments, child task checklists. All configurable.

## Key Design Elements

- Workspace lifecycle tied to task scheduling (create at Queued→Active, persist through idle states, cleanup at terminal states)
- Worktree verification for checkpoint resume (valid/recoverable/lost)
- Child PR strategy: merge_into_parent (default) or individual_prs
- Workspace object schema with full git state tracking
- Comm plugin shared contract: send, receive, query, sync capabilities
- Query Router pattern: comm.message_received → disambiguate (query vs task response) → route to data source → compose response
- GitHub label scheme: `engineer:{state}` (mutually exclusive)

## Post-Design Review

Traced all 5 user flows through both new designs. Found and fixed:

1. **Gap: Child GitHub issue creation** -- Flow 5 requires creating GitHub issues for child tasks. Added `createIssue` and `updateIssue` to comm plugin interface. Documented the explicit flow: Orchestrator creates internal tasks (Task Engine) → creates GitHub issues (comm plugin) → links them (updates external_ref).

2. **Gap: Progressive merge trigger** -- Active.Supervising doesn't have git permissions, so the parent Orchestrator can't call `mergeBranch`. Fixed by making the Task Engine own progressive merge as part of child completion handling (infrastructure work, like workspace creation/cleanup).

3. **Inconsistency: "Cancelled" state** -- Workspace Manager cleanup table referenced a state that doesn't exist. Clarified that cancellation is Failed with reason "cancelled."

4. **Inconsistency: `commentOnPR` overlap** -- Both Workspace Manager and Comm Plugin had this operation. Removed from comm plugin. PR lifecycle (including review comment replies) is Workspace Manager territory. Comm plugins handle issue-level operations.
