## Decisions Made

1. **`pending_pr_event` stores the event type, not the full payload** *(refinement of the approved
   new-column choice)*. `entryFor` routes on type alone; storing the type is S6-thin-faithful and sidesteps
   the import cycle. Chosen over storing the full `PrEvent` (which would need an 11-importer `ExternalRef`
   move) or reusing `review` (overloads a durable field with a consume-once signal).
2. **Rework context reaches the re-entered agent via the runner's `carry`** *(seeded at re-entry)*. Reuses
   the existing carry rendering (`gather`/`implement`/`design`) — no new prompt plumbing. Comments come from
   `review.feedback_rounds` (the poller appends them, as the legacy handler did); CI/conflict re-derive live.
3. **7a handles rework events only** *(Farzam's pre-split)*. Merge-class events (`pr_ready_to_merge`,
   `pr_merged`) and the `/approve` promotion are 7b. An authorized `/approve` (and a bare changes-requested
   with no text) is suppressed from the actionable set so a poll never spuriously reworks on an approval,
   and nothing completes-without-merging while `auto-merge` is shelled.
4. **The poller is stateless and the legacy feedback-event path is deleted in full.** The DB re-queue +
   `accommodated_comment_ids` dedup replace the in-memory `emittedFeedbackKeys`/`approvedAwaitingCI` maps and
   the `task.feedback_received` event flow.
