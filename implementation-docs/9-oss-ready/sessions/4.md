# Session 4 — Dashboard Planning (Slice 3)

**Date:** 2026-05-11
**Slice:** 03-dashboard
**Phase:** Requirements Gathering → Planning → Complete (planning only)

## What Happened

Planned the complete dashboard frontend rewrite (Slice 3). This is a planning-only session — no code written. The full plan is documented in `slices/03-dashboard.md` for future sessions to execute against.

Key requirements gathered through Q&A:
- Full frontend rewrite in a proper framework, leveraging existing libraries
- Focus on observability — total transparency into The Engineer at any moment
- Read-heavy control room: admin sees everything, responds to blocked tasks, can cancel running tasks
- Useful over pretty — leverage libs for aesthetics, spend effort on data and UX
- No tests for dashboard (peripheral service)
- Backend refines incrementally, not a big-bang rewrite

## Decisions Made

1. **Tech stack:** React 19 + Vite + shadcn/ui + Tailwind CSS v4 + TanStack Query + TanStack Table + React Router v7 + Recharts
2. **Layout:** Sidebar navigation (Grafana/Datadog pattern) — more vertical space for data
3. **Information architecture:** 5 views (Overview, Tasks, Activity, Metrics, Errors) — consolidated from 8 tabs
4. **Immersive task detail:** When you drill into a task, everything is scoped to that one task. No cross-task noise.
5. **State management:** TanStack Query + URL params. No Zustand — component state + URL is sufficient.
6. **SSE integration:** Global SSE provider with centralized TanStack Query cache invalidation
7. **No tests:** Delete existing dashboard API tests. Peripheral service, type safety is defense enough.
8. **Backend changes incremental:** CORS/SPA serving (Session 5), cancel endpoint (Session 6), metrics optimization (Session 7)
9. **Project structure:** React source in `src/dashboard/client/`, own tsconfig/vite config, builds to `dist/dashboard/`
10. **Session phasing:** 3 implementation sessions (5-7) + optional polish (8)
