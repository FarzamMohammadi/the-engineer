# Session 068 — 2026-03-22

## What Happened

RRPIR methodology design session. Started with RPI research — studied HumanLayer ACE, Goose RPI, Tyler Burleigh RPIR, LinearB Ralph loops, patrob FAR/FACTS scales. During brainstorming, Farzam surfaced a fundamental insight: The Engineer should not compete with CLI tools, it should wield them. This led to the CLI-native architecture pivot (revises D143) — CLI tools are full agents, not inference providers. The Engineer's value is orchestration, not reimplementing CLI capabilities.

Designed The Engineer's own methodology: RRPIR (Requirements Gathering → Research → Planning → Implementation → Review). Two original contributions beyond existing RPI/RPIR: (1) Requirements Gathering as a universal fallback any phase can invoke when stuck, and (2) a multi-phase configurable Review pipeline. Renamed intake_analysis → requirements_gathering, removed fast-path (quality over speed), designed thoughts/ directory for file-based handoffs, signal protocol for CLI output parsing, plan checkboxes for crash-safe progress.

Six design concerns flagged with resolution sessions: signal parsing reliability (069), universal fallback routing (070), cost management (071), cross-task knowledge (future), decomposition timing (070), estimation (future).

Created rrpir-design.md as the definitive architecture document. Updated overview.md (5 strategic decisions), roadmap.md (RRPIR sessions 069-073), status.md.

## Decisions Made

1. **CLI-Native Agent Architecture** (revises D143 from Layer 6/S052) — CLI tools are full agents with native capabilities. The Engineer orchestrates them. Agent loop (agent-loop.ts, action-executor.ts, phase-tools.ts) to be removed.
2. **RRPIR Methodology** — Requirements Gathering → Research → Planning → Implementation → Review. The Engineer's own methodology.
3. **Requirements Gathering as Universal Fallback** (revises intake_analysis from Layer 2/6) — Any phase can invoke it. People Directory + Communication plugins contact the right people. Task blocks until response.
4. **Remove Fast-Path** (revises D141) — Every task gets full RRPIR. Quality over speed.
5. **Multi-Phase Configurable Review Pipeline** (revises self-review from Layer 2/6) — Separate CLI sessions per review lens. Extensible via config.
6. **thoughts/ Directory** — File-based handoffs: requirements.md, research.md, plan.md, review/*.md, refinements.md. Appear in PRs.
7. **Signal Protocol** — `ENGINEER_SIGNAL: {JSON}` at end of CLI output for reliable phase transition parsing.
8. **Forward-Only Documentation** — All new work in 8-refinement-v2/. Decisions reference prior decisions by number for lineage but don't modify old files.
