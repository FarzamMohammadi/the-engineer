## Decisions Made

1. **Cause chain propagation via constructor option** — Extend existing error constructors with `(message, options?: { cause })` rather than introducing a helper or wrapper class. Standard `Error` semantics, minimal surface area, zero new abstraction.
2. **`TracedObserver` as a separate class, not a mutation of `Observer`** — `withTrace(traceId)` returns a new instance so the parent observer stays unbound; trace context is per-task and shouldn't leak across task boundaries.
3. **Trace injection at the top of `Orchestrator.executeTask`** — One integration point where `traceId` is born. Derived `OrchestratorContext` (`{ ...this.ctx, observer: tracedObserver }`) passes it transparently to the phase runner without leaking the trace concern into any phase handler.
4. **Capability identifier format `${manifest.type}_adapter`** — Stable, machine-grep-friendly label (`trigger_adapter`, `communication_adapter`, etc.) so degradation logs can be filtered by capability without parsing prose.
5. **Adapter `base.ts` init failure logs `adapterType` + `critical`** — Operators need to know whether a failed plugin took down a critical capability or just a swappable one; this answers it without cross-referencing the manifest.
6. **`retryable` semantics: transient resource issues only** — `VersionConflictError`, `WorkspaceNotReadyError`, `LlmUnavailableError` are retryable; permission/validation/invariant errors are not. The orchestrator and daemon can branch on this without inspecting tags.
