## Decisions Made

1. **File-first architecture** — session-result.json files (not CLI text parsing) drive phase routing. Each phase writes .md + session-result.json.
2. **Task-scoped thoughts/ directory** — `thoughts/{date}-{thoughts_id}/` with phase subdirs. thoughts_id comes from trigger plugin (Core never derives it).
3. **session-result.json schema** — 3 fields: status (ready/need_more_info/error), next_phase (Phase enum), summary (one-line for dashboard).
4. **Template pre-fill with valid options** — Orchestrator writes placeholder template before CLI runs. If CLI doesn't fill it, defaults to "ready" + expected next phase.
5. **No getContinueArgs** (deferred) — session continuation via CLI `--continue` flags deferred until process-level session management is wired. Nudge defaults instead of burning inference calls.
6. **All prompts CLI-native** — shared helpers in format.ts (buildRRPIROverview, buildKnowledgeSection, buildRepoOverview). Full methodology in system prompt only, brief orientation in user prompt.
