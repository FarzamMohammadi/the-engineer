## Decisions Made

1. **`isTaskEligible` extracted to a pure top-level function in
   `task-scheduler.ts`.** Signature: `(task: {id, not_before}, now: number) => boolean`.
   The plan proposed exposing it on the scheduler interface and injecting it into
   preemption-manager via DI. Pure top-level is cleaner: scheduler and
   preemption-manager both consume it directly, the clock is an argument rather
   than a closed-over dependency, and the function has zero state. Preemption-manager
   now filters `not_before`-blocked candidates *before* picking so it can't waste an
   eviction on a candidate that wouldn't dispatch anyway.

2. **`Dispatch` split into payload + runtime types.** `DispatchSchema` keeps the
   serializable shape (still parsed by unit tests). The runtime `Dispatch` type
   extends `DispatchPayload` with `signal: AbortSignal`. The plan implied adding
   `signal` to the Zod schema (e.g., `z.custom<AbortSignal>(...)`). Splitting honors
   Parse-Don't-Validate honestly: `AbortSignal` is runtime infrastructure, not
   parsed input. The schema remains a faithful description of what crosses
   serialization boundaries.

3. **`dispatch-tracker.drain` synthesizes the late callback for stragglers after
   the shared timeout.** Plan intent was that stragglers stayed tracked and their
   late callback fired only if/when the orchestrator promise eventually settled.
   That broke the shutdown contract in v1: until Slice 8 plumbs the signal through
   `phase-runner → llm-caller → LLM plugins`, in-flight LLM calls cannot be
   aborted, so the promise never settles and the daemon can't actually shut down.
   The synthesized callback restores best-effort shutdown semantics (the
   pre-Session-3 behavior) while keeping the single-tracker ownership.

4. **Late-callback termination wins over runner error.** When `terminate()` is
   called and the runner then rejects (e.g., the abort propagates as an error), the
   tracker routes the callback as `Outcomes.terminated` with the recorded reason,
   not as `onError`. The termination request is authoritative — the runner's error
   becomes a debug breadcrumb.

5. **Cost-limit notifications stay synchronous inside `cost-limit-queue.process()`.**
   The state transition becomes async (via the late callback after the terminate
   routing settles), but the owner-facing notifications must fire now — the owner
   needs to know the limit hit synchronously, not whenever the in-flight LLM call
   eventually winds down. Mirrors the research's Option A recommendation.
