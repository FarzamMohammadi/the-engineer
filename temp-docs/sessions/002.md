## Decisions Made

1. **Goals before architecture** — defined where we're going before designing how to get there. Goals doc is the north star for all architectural decisions.
2. **Derive from proven systems** (new philosophy) — study how CPUs, OSes, databases, CI/CD solved analogous problems, then derive our approach from theirs.
3. **Isolation as survival** (new philosophy) — each task is its own universe. Nothing bleeds across boundaries.
4. **Task states from CPU model** — Intake, Queued, Active, Blocked, Completed, Failed. Blocked carries rich status details (why, efforts made, who contacted, what's needed).
5. **Blocked is not passive** — agent must attempt self-unblock first (research, investigate, reach out with precise questions) before truly blocking.
6. **Prompt architecture direction** — small orchestrator prompt + phase-specific reference docs loaded on-demand based on state. Not a hard token limit, but smart context loading.
7. **The skeleton and plugins** — core is invariant (daemon, task engine, state machine, orchestrator). Everything that varies by use case is a plugin (triggers, comms, LLMs, tools). Skeleton can be non-LLM for cost efficiency.
8. **No hardcoded "never" rules** — all guardrails are configurable. The agent makes judgment calls within its configured boundaries, like a real engineer follows company policy.
9. **Self-decomposition** — large tasks get broken into sub-tasks/tickets that trigger the agent recursively.
10. **Proactive behavior** — the "holy shit it's alive" moment. Configurable: some users want a soldier, some want a partner.
11. **Removed premature artifacts** — BOOT.md and memory/ deleted. These are outputs of architecture, not inputs.
