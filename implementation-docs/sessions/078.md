# Session 078 — 2026-03-27/28

## What Happened

Implemented the full Startup & Configuration refinement from plan through execution across two sessions. CLI consolidated from 14 to 6 commands. Built a new setup module with explicit per-adapter-type plugin selection, .env-based secret management, detection derived from plugin manifests, and dynamic per-plugin config prompts via `promptForConfig`. Removed all hardcoded doctor connectivity checks and hardcoded plugin references from the setup module. Multiple expert panel reviews shaped the design. Config generation merges user values into templates, preserving `${VAR}` refs. Zero hardcoded plugin names in the setup flow.

## Decisions Made

1. `engineer start` is the single entry point — absorbs setup/init/prepare
2. Command surface: 14→6 (start, stop, status, logs, doctor, why). Removed dashboard, install, create-plugin as premature.
3. Explicit plugin selection per adapter type (not auto-detection) — user chooses, detection shows availability
4. `ADAPTER_TYPE_CONFIGS` centralized registry drives selection flow (selectionMode, setupOrder, required, label)
5. `combined_with` on PluginManifestSchema for plugin family grouping (GitHub trigger/comm/hosting)
6. Detection derives binary/env lists from manifest `requirements` — no hardcoded detection lists
7. `~/.engineer/.env` for secrets (0o600, loaded before config resolution, env vars take precedence)
8. `promptForSecrets()` dynamically scans generated template content for ${VAR} patterns — no hardcoded token names
9. Deleted `enabled` field from manifests (dead code), deleted `SEED_TEMPLATES` (unused)
10. Removed hardcoded doctor categories 7-8 (GitHub/Telegram connectivity) — category 4 already does dynamic scanning
11. Communication is the only optional adapter type (required: false)
12. `seed-example/` flattened to `plugins/` only — reset script uses `--plugins` flag
13. `promptForConfig` optional function on `BuiltinPlugin` — plugins declare their own interactive prompts, setup calls generically
14. `generateConfigFiles` merges user config INTO templates (preserves `${VAR}` refs from templates)
